

### 模块一：进程、线程与并发基础

#### 1. 进程与线程的核心定义与对比

- **进程 (Process)**：程序由指令和数据组成，将指令加载至 CPU、数据加载至内存，并管理 IO 的过程，就开启了一个进程，它可以视为程序的一个实例。  
- **线程 (Thread)**：一个进程内可以分为多个线程。线程是一个指令流，负责将指令交给 CPU 执行。  
- **二者对比**：Java 中线程是最小调度单位，进程是资源分配的最小单位。进程间相互独立，通信复杂（如 IPC、HTTP），且上下文切换成本高；而线程存在于进程内，共享进程内存，通信简单且切换成本低。  

#### 2. 并发与并行 (Concurrency vs Parallelism)

- **并发**：在单核 CPU 下，操作系统任务调度器将 CPU 的时间片（如 Windows 下约 15 毫秒）分给不同程序，由于切换极快，宏观上感觉是同时运行，总结为“微观串行，宏观并行”。Rob Pike 定义并发为“同一时间**应对** (dealing with) 多件事情的能力”。  
- **并行**：在多核 CPU 下，每个核心可以分别调度运行线程，此时线程是真正同时运行的。Rob Pike 定义并行为“同一时间**动手做** (doing) 多件事情的能力”。  

#### 3. 同步与异步

- **同步**：调用方需要等待结果返回，才能继续运行。  
- **异步**：调用方不需要等待结果返回，就能继续运行。常用于读取耗时磁盘文件、Tomcat 异步 Servlet、或 UI 程序中，以避免阻塞主线程。  

### 模块二：Java 线程核心机制

#### 1. 创建线程的三种方式

- **方法一：继承 `Thread` 类**。将线程和任务合并在一起。  
- **方法二：实现 `Runnable` 接口配合 `Thread`**。把【线程】和【任务】分开，让任务类脱离 Thread 继承体系，更灵活，且容易与线程池等高级 API 配合。  
- **方法三：`FutureTask` 配合 `Thread`**。`FutureTask` 接收 `Callable` 类型的参数，用来处理有返回结果的情况，主线程可通过 `get()` 方法同步等待执行结果。  

Java

```
// 方法三：获取线程返回结果的简易代码
FutureTask<Integer> task = new FutureTask<>(() -> {
    return 100; // 异步耗时任务
});
new Thread(task, "t3").start();
Integer result = task.get(); // 主线程在此阻塞，同步等待结果
```

#### 2. 底层机制与状态流转

- **栈与栈帧**：JVM 内存中，每个线程启动后会分配一块虚拟机栈。栈由多个栈帧（Frame）组成，对应每次方法调用占用的内存，每个线程只能有一个活动栈帧。  
- **上下文切换 (Context Switch)**：因 CPU 时间片用完、垃圾回收、更高优先级线程抢占或调用了 `sleep`/`yield`/`wait` 等方法，CPU 会转而执行其他线程。此时操作系统会通过**程序计数器 (Program Counter Register)** 保存当前线程下一条指令的地址及栈帧状态。频繁切换会影响性能。  
- **Java API 的六种状态**：
  - `NEW`：创建了线程对象，还未调用 `start()`。  
  - `RUNNABLE`：涵盖了操作系统的可运行、运行和阻塞（由于 BIO 导致的阻塞在 Java 中仍视为可运行）。  
  - `BLOCKED`、`WAITING`、`TIMED_WAITING`：是对操作系统阻塞状态的细分。  
  - `TERMINATED`：线程代码运行结束。  

#### 3. 常见 API 细节解析

- `start()` 与 `run()`：直接调用 `run()` 只是在主线程中同步执行代码；调用 `start()` 才是真正让线程进入就绪状态并异步执行，且只能调用一次。  
- `sleep()` 与 `yield()`：`sleep()` 让线程进入 `Timed Waiting` 状态，不会释放锁；`yield()` 仅提示调度器让出 CPU 时间片，线程进入 `Runnable` 就绪状态。  
- `join()`：等待线程运行结束，常用于解决主线程需要子线程计算结果的同步问题。  
- `interrupt()`：打断 `sleep`、`wait`、`join` 的阻塞线程会抛出异常并**清除**打断标记；打断正常运行的线程**不会清除**打断标记。  
- **守护线程 (Daemon)**：只要其他非守护线程运行结束，即使守护线程代码没执行完也会强制结束（如垃圾回收器、Tomcat 的 Acceptor 线程）。  

### 模块三：共享模型之并发问题

#### 1. 问题的产生原理 (字节码交错)

- Java 中对静态变量的自增（`i++`）和自减（`i--`）不是原子操作。  
- `i++` 在底层字节码分为多步：`getstatic` (读取主内存变量到工作内存)、`iconst_1` (准备常量1)、`iadd` (加法)、`putstatic` (写回主内存)。  
- 在多线程环境下，由于上下文切换，这些底层指令可能发生交错（例如线程 1 读取了 0，线程 2 也读取了 0 并减 1 写入 -1，线程 1 随后加 1 写入 1，导致结果被覆盖），这就是产生安全问题的根本原因。  

#### 2. 核心概念定义

- **临界区 (Critical Section)**：一段代码块内如果存在对共享资源的多线程读写操作，这段代码块就称为临界区。  
- **竞态条件 (Race Condition)**：多个线程在临界区内执行，由于代码的执行序列不同而导致结果无法预测的现象。  

### 模块四：synchronized 与互斥锁

#### 1. synchronized 的工作原理

- `synchronized` 俗称【对象锁】，采用互斥的方式让同一时刻至多只有一个线程能持有对象锁。  
- 它可以保证临界区内的代码对外是不可分割的（原子性），不会被线程上下文切换所打断。当线程获取不到锁时，会被阻塞（进入 `BLOCKED` 状态）等待。  

#### 2. 方法上的 synchronized (线程八锁核心)

- **修饰普通方法**：`public synchronized void test()` 等价于在方法内部使用 `synchronized(this)`，锁住的是当前实例对象。  
- **修饰静态方法**：`public synchronized static void test()` 等价于在方法内部使用 `synchronized(Test.class)`，锁住的是该类的 Class 类对象。  
- **排队规则**：不加 `synchronized` 的方法好比不遵守规则翻窗户的人，不需要排队等待锁。不同对象锁之间互不干扰。  

### 模块五：变量的线程安全分析

### 1. 成员变量与静态变量

- 如果没有被共享，则是线程安全的。  
- 如果被共享：只有读操作是安全的；如果有读写操作，则该代码属于临界区，是非线程安全的。  

#### 2. 局部变量与对象逃离

- 局部变量本身是线程安全的，因为每个线程调用方法时，会在各自的栈帧中创建局部变量的副本，不存在共享。  
- **特例（引用逃离）**：如果局部变量引用了对象，且该对象逃离了方法的作用范围（例如作为参数传递给其他方法，或该方法被子类重写并开启新线程操作该对象），则需要考虑线程安全问题。  
- **闭包原则**：这也是为什么提倡将方法或类修饰为 `private` 或 `final`，能够有效防止子类重写方法从而破坏不可变性和线程安全性。  

#### 3. 常见线程安全类

- `String`、`Integer`、`StringBuffer`、`Vector`、`Hashtable` 以及 `java.util.concurrent` 包下的类都是线程安全的。  
- **注意陷阱**：这里的线程安全是指它们**单个方法**的调用是原子的。但如果是多个方法的**组合**操作（例如先判断 `if(table.get("key") == null)` 再执行 `table.put("key", value)`），由于两次方法调用之间可能发生上下文切换，这种组合操作依然不是原子的，不是线程安全的。  

#### 4. 不可变类的安全性

- 像 `String` 和 `Integer` 这种其内部状态不可改变的类是线程安全的[cite: 1]。

Java

```
// String 中类似 substring 的方法是如何保证安全的？
// 答案：保护性拷贝 (Defensive Copy)
public String substring(int beginIndex) {
    // 内部其实是 new 了一个全新的 String 对象返回，不会修改原来的数据[cite: 1]
    return new String(value, beginIndex, subLen);
```
