### 8. J.U.C 无锁并发工具：原子类 (Atomic)

#### 8.1 原子整数 (AtomicInteger)

提供对基本数据类型的原子操作。利用函数式接口（Lambda），可以极其优雅地实现复杂的原子计算。

Java

```
AtomicInteger i = new AtomicInteger(0);

// 获取并更新（其中函数能保证原子性，但绝对不能有副作用）
System.out.println(i.getAndUpdate(p -> p - 2)); 
System.out.println(i.updateAndGet(p -> p + 2)); 

// 获取并计算（利用额外参数 x 避免 Lambda 外部变量 final 的限制）
System.out.println(i.getAndAccumulate(10, (p, x) -> p + x));
System.out.println(i.accumulateAndGet(-10, (p, x) -> p + x));
```

#### 8.2 原子引用与 ABA 问题破解

`AtomicReference` 可以对引用类型（对象）进行原子的 `compareAndSet` (CAS) 操作，但由于 CAS 只是对比“值/地址”是否一致，会引发经典的 **ABA 问题**（变量被别的线程从 A 改成 B，又改回了 A，当前线程误以为没被改过而操作成功）。

- **`AtomicStampedReference` (带版本号)**：不仅对比引用的地址，还对比**版本号 (Stamp)**。每次修改变量时版本号 +1，完美获知变量被修改了几次，彻底解决 ABA 问题。
- **`AtomicMarkableReference` (带标记位)**：如果你不在乎变量被改了多少次，**只想知道它“是否被改过”**，可以使用这个类。它维护一个 `boolean` 类型的标记，内存占用比加版本号更小。

#### 8.3 字段更新器 (FieldUpdater)

如果你只想针对对象的某一个特定的域（Field）进行原子更新，而不是把整个对象变成原子引用，可以使用字段更新器。

- **核心限制**：被更新的字段**必须且只能**配合 `volatile` 关键字修饰，否则会抛出异常。

Java

```
public class Test5 {
    // 必须用 volatile 修饰，保证可见性
    private volatile int field; 

    public static void main(String[] args) {
        // 创建针对 Test5 类中 "field" 属性的更新器
        AtomicIntegerFieldUpdater<Test5> fieldUpdater = 
            AtomicIntegerFieldUpdater.newUpdater(Test5.class, "field");
            
        Test5 test5 = new Test5();
        
        // compareAndSet(对象, 期望值, 更新值)
        fieldUpdater.compareAndSet(test5, 0, 10); // 修改成功，field = 10
        System.out.println(test5.field);
        
        fieldUpdater.compareAndSet(test5, 10, 20); // 修改成功，field = 20
        System.out.println(test5.field);
        
        fieldUpdater.compareAndSet(test5, 10, 30); // 修改失败（期望值10与当前值20不符），保持 20
        System.out.println(test5.field);
    }
}
```

#### 8.4 原子累加器 (LongAdder) - 🌟 高并发杀手锏

在极高并发的场景下（如统计网站总访问量），如果多个线程死磕同一个 `AtomicLong`，由于 CAS 会频繁失败，导致大量线程自旋空转，CPU 飙升。`LongAdder` 应运而生。

- **设计思想 (空间换时间 / 分段锁思想)**：`LongAdder` 内部维护了一个 `Base` 值和一个 `Cell[]` 数组。
  - **竞争较低时**：直接 CAS 累加到 `Base` 变量上。
  - **竞争激烈时**：多线程会通过 Hash 算法被分散到不同的 `Cell` 单元格中分别进行累加，互不干扰，极大降低了自旋重试的概率。
  - **获取结果**：调用 `sum()` 方法时，会将 `Base` 和所有 `Cell` 的值汇总返回。

**实战用法：**

Java

```
LongAdder adder = new LongAdder();

// 多个线程并发调用 increment 或 add 进行累加
adder.increment(); // 自增 1
adder.add(10);     // 增加 10

// 最终获取总和 (非精确强一致，但在统计场景足够高效)
long total = adder.sum(); 
```
