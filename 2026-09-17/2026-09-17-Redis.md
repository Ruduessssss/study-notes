# Redis 常用命令与数据结构学习笔记

## 一、 通用规范与基础格式

- **String类型的三种格式**：字符串、int、float。
- **Redis 的 Key 格式规范**：通常推荐使用 `[项目名]:[业务名]:[类型]:[id]` 的格式来进行命名与层级划分。

## 二、 String 类型的常见命令

- `SET`：添加或者修改已经存在的一个String类型的键值对。
- `GET`：根据key获取String类型的value。
- `MSET`：批量添加多个String类型的键值对。
- `MGET`：根据多个key获取多个String类型的value。
- `INCR`：让一个整型的key自增1。
- `INCRBY`：让一个整型的key自增并指定步长，例如：`incrby num 2` 让num值自增2。
- `INCRBYFLOAT`：让一个浮点类型的数字自增并指定步长。
- `SETNX`：添加一个String类型的键值对，前提是这个key不存在，否则不执行。
- `SETEX`：添加一个String类型的键值对，并且指定有效期。

## 三、 Hash 类型的常见命令

- `HSET key field value`：添加或者修改hash类型key的field的值。
- `HGET key field`：获取一个hash类型key的field的值。
- `HMSET`：批量添加多个hash类型key的field的值。
- `HMGET`：批量获取多个hash类型key的field的值。
- `HGETALL`：获取一个hash类型的key中的所有的field和value。
- `HKEYS`：获取一个hash类型的key中的所有的field。
- `HVALS`：获取一个hash类型的key中的所有的value。
- `HINCRBY`：让一个hash类型key的字段值自增并指定步长。
- `HSETNX`：添加一个hash类型的key的field值，前提是这个field不存在，否则不执行。

## 四、 List 类型的常见命令

- `LPUSH key element ...`：向列表左侧插入一个或多个元素。
- `LPOP key`：移除并返回列表左侧的第一个元素，没有则返回nil。
- `RPUSH key element ...`：向列表右侧插入一个或多个元素。
- `RPOP key`：移除并返回列表右侧的第一个元素。
- `LRANGE key star end`：返回一段角标范围内的所有元素。
- `BLPOP`和`BRPOP`：与LPOP和RPOP类似，只不过在没有元素时等待指定时间，而不是直接返回nil。

## 五、 Set 类型的常见命令

- `SADD key member ...`：向set中添加一个或多个元素。
- `SREM key member ...`：移除set中的指定元素。
- `SCARD key`：返回set中元素的个数。
- `SISMEMBER key member`：判断一个元素是否存在于set中。
- `SMEMBERS`：获取set中的所有元素。
- `SINTER key1 key2 ...`：求key1与key2的交集。
- `SDIFF key1 key2 ...`：求key1与key2的差集。
- `SUNION key1 key2 ...`：求key1和key2的并集。

## 六、 SortedSet 类型的常见命令

- `ZADD key score member`：添加一个或多个元素到sorted set，如果已经存在则更新其score值。

- `ZREM key member`：删除sorted set中的一个指定元素。

- `ZSCORE key member`：获取sorted set中的指定元素的score值。

- `ZRANK key member`：获取sorted set中的指定元素的排名。

- `ZCARD key`：获取sorted set中的元素个数。

- `ZCOUNT key min max`：统计score值在给定范围内的所有元素的个数。

- `ZINCRBY key increment member`：让sorted set中的指定元素自增，步长为指定的increment值。

- `ZRANGE key min max`：按照score排序后，获取指定排名范围内的元素。

- `ZRANGEBYSCORE key min max`：按照score排序后，获取指定score范围内的元素。

- `ZDIFF`、`ZINTER`、`ZUNION`：求差集、交集、并集。

  

  

  

  
  
  
  
  
  
  
  
  
  
  在 Java 和 Spring Boot 开发中，**Jedis** 和 **`StringRedisTemplate`** 都是用来与 Redis 进行交互的常见工具，但它们的定位、设计理念和使用方式有很大不同。   
  
  以下是它们的详细对比与使用总结：   
  
  
  
  ## Jedis和StringRedisTemplate


  ### 一、 核心概念与区别   

  | **维度**       | **Jedis**                                                    | **StringRedisTemplate**                                      |
  | -------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
  | **本质**       | Redis 官方推荐的**底层 Java 客户端**。                       | Spring Data Redis 提供的**高层模板类**（继承自 `RedisTemplate`）。 |
  | **API 设计**   | **直观、命令式**：方法名与 Redis 官方命令几乎完全一致（如 `jedis.set()`、`jedis.hget()`）。 | **面向对象、结构化**：通过操作 Ops 接口（如 `opsForValue()`、`opsForHash()`）来划分数据类型。 |
  | **线程安全**   | **线程不安全**。多线程环境下需要使用 `JedisPool` 连接池来保证安全。 | **线程安全**。可以直接在多线程（如 Spring Bean）中安全注入和使用。 |
  | **序列化方式** | 主要是字符串/字节数组，需开发者自己手动处理复杂对象的序列化（如 JSON）。 | 默认采用 **`StringRedisSerializer`**，专门针对 String 键值对进行优化。 |

  ### 二、 Jedis 的使用总结   

  Jedis 类似于 JDBC，属于较底层的直连或连接池操作方式。

  #### 1. 引入依赖   

  XML

  ```
  <!-- 纯 Jedis 依赖 -->
  <dependency>
      <groupId>redis.clients</groupId>
      <artifactId>jedis</artifactId>
  </dependency>
  ```

  #### 2. 代码示例（使用连接池）

  Jedis 通常需要配合 `JedisPool` 使用，用完后必须手动关闭或归还连接。

  Java

  ```
  // 1. 初始化连接池
  JedisPoolConfig poolConfig = new JedisPoolConfig();
  poolConfig.setMaxTotal(30);
  JedisPool jedisPool = new JedisPool(poolConfig, "localhost", 6379);
  
  // 2. 从连接池获取 Jedis 对象
  try (Jedis jedis = jedisPool.getResource()) {
      // 3. 执行 Redis 命令
      jedis.set("name", "张三");
      String name = jedis.get("name");
      System.out.println(name);
  } catch (Exception e) {
      e.printStackTrace();
  }
  ```

  ### 三、 `StringRedisTemplate` 的使用总结

  `StringRedisTemplate` 是 Spring Boot 项目中最常用的 Redis 操作工具（Spring 2.x 后默认底层连接池通常为 Lettuce，但 API 保持统一）。它的键和值默认都是 `String` 类型。   

  #### 1. 引入依赖

  在 Spring Boot 中只需引入 Spring Data Redis 起步依赖：

  XML

  ```
  <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-data-redis</artifactId>
  </dependency>
  ```

  #### 2. 代码示例（注入并使用）

  Spring 容器会自动管理连接的获取与释放，开发者开箱即用。

  Java

  ```
  @RestController
  public class RedisController {
  
      @Autowired
      private StringRedisTemplate stringRedisTemplate;
  
      public void testString() {
          // 1. 操作 String 类型
          stringRedisTemplate.opsForValue().set("city", "北京");
          String city = stringRedisTemplate.opsForValue().get("city");
  
          // 2. 设置过期时间
          stringRedisTemplate.opsForValue().set("code", "1234", 60, TimeUnit.SECONDS);
  
          // 3. 操作 Hash 类型
          stringRedisTemplate.opsForHash().put("user:1001", "name", "李四");
          String userName = (String) stringRedisTemplate.opsForHash().get("user:1001", "name");
      }
  }
  ```

  > **提示**：如果要存取复杂的 Java 对象，通常会配合 `Jackson` 将对象转成 JSON 字符串，再用 `StringRedisTemplate` 存储。

  ### 四、 选型建议   

  1. **在 Spring Boot 项目中**：   
     - **强烈推荐使用 `StringRedisTemplate`**（或者它的泛型兄弟 `RedisTemplate`）。它完美融入了 Spring 生态，由框架自动帮你管理连接池，代码更简洁安全，且不易发生连接泄漏。   
  2. **在非 Spring 或轻量级纯 Java 项目中**：   
     - 可以选择 **Jedis**，它轻量、直接，没有 Spring 框架的沉重依赖。   
     
       在 Spring Data Redis（以及 Redis 原生命令）中，基本上遵循这样一个规律：**“查单值返回 `null`，查集合返回空集合”**。
     
       我们可以把常见的情况分为以下两类：
     
       ### 1. 查不到时返回 `null` 的情况（单值操作）
     
       当你试图获取一个具体的“值”时，如果 Key 不存在，Redis 会返回 `nil`，Spring 就会将其解析为 `null`。
     
       - **String 类型（最常见）**
     
         Java
     
         ```
         // 如果 key 不存在，返回 null
         String value = stringRedisTemplate.opsForValue().get("not_exist_key"); 
         ```
     
       - **Hash 类型中的单个字段**
     
         Java
     
         ```
         // 如果 key 不存在，或者 field 不存在，都返回 null
         Object fieldVal = stringRedisTemplate.opsForHash().get("hash_key", "not_exist_field"); 
         ```
     
       - **List 类型中的单个元素**
     
         Java
     
         ```
         // 按索引获取单个元素，如果 key 不存在返回 null
         String item = stringRedisTemplate.opsForList().index("list_key", 0);
         ```
     
       ### 2. 查不到时返回空集合的情况（批量/集合操作）
     
       当你调用的 API 是用来获取一个“范围”或“全部内容”时（底层数据是 Hash、List、Set 等集合结构），如果 Key 不存在，Spring 会返回一个**大小为 0 的空集合**（如 `[]` 或 `{}`），而不是 `null`。
     
       - **Hash 类型（查全部字段）**
     
         Java
     
         ```
         // 如果 key 不存在，返回一个空的 HashMap：{}
         Map<Object, Object> map = stringRedisTemplate.opsForHash().entries("not_exist_hash"); 
         ```
     
       - **List 类型（查列表范围）**
     
         Java
     
         ```
         // 如果 key 不存在，返回一个空的 ArrayList：[]
         List<String> list = stringRedisTemplate.opsForList().range("not_exist_list", 0, -1);
         ```
     
       - **Set / ZSet 类型（查所有成员）**
     
         Java
     
         ```
         // 如果 key 不存在，返回一个空的 HashSet：[]
         Set<String> set = stringRedisTemplate.opsForSet().members("not_exist_set");
         ```
