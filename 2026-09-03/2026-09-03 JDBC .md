### 一、 JDBC 简述

- **定义**：JDBC (Java Database Connectivity) 是 Java 官方提供的一套用于连接和操作各大关系型数据库的统一标准 API。
- **核心价值**：它是所有 Java 数据库操作的底层基石。你之前学习的 MyBatis-Plus 等高级框架，底层全都是对 JDBC 的封装。
- **运行机制**：Java 提供标准接口，各大数据库厂商（如 MySQL）提供具体的实现类（驱动包/Driver）。

### 二、 DriverManager (驱动管理类)

- **核心作用**：负责加载和注册数据库驱动，并负责和数据库建立最原始的物理连接。
- **主要方法**：`DriverManager.getConnection(url, username, password)`。
- **现代开发痛点**：每次调用都会新建一个物理连接，极其耗时且消耗系统资源，因此在企业开发中通常会被“数据库连接池”取代。

### 三、 Connection (数据库连接对象)

- **核心地位**：它是 Java 程序与数据库沟通的“桥梁”，拿到它才意味着真正连上了数据库。
- **两大核心职责**：
  1. **获取 SQL 执行器**：调用 `prepareStatement(sql)` 获取预编译执行对象。
  2. **管理事务**：
     - 开启事务：`setAutoCommit(false)`
     - 提交事务：`commit()`
     - 回滚事务：`rollback()` (通常在 catch 异常时调用)

### 四、 Statement (SQL 执行对象)

- **`Statement` (普通执行对象)**：用于执行直接拼接好的静态 SQL。存在严重的**SQL 注入安全漏洞**，企业开发中严禁用于处理用户输入的动态参数。
- **`PreparedStatement` (预编译执行对象，企业标配)**：
  - **防注入原理**：使用 `?` 作为参数占位符，底层对传入的参数进行严格的类型限定和字符转义。
  - **参数赋值**：通过 `setInt(索引, 值)` 或 `setString(索引, 值)` 为问号赋值（索引从 1 开始）。
  - **核心执行方法**：
    - `executeUpdate()`：专门用于执行 **增 (INSERT)、删 (DELETE)、改 (UPDATE)**，返回受影响的行数 (int)。
    - `executeQuery()`：专门用于执行 **查 (SELECT)**，返回查询结果集。

### 五、 ResultSet (结果集对象)

- **核心作用**：封装了执行 `SELECT` 查询语句后，数据库返回的所有表格数据。
- **游标机制**：初始状态下，内置的游标停留在表格的“表头”上方，没有指向任何实际数据。
- **标准解析套路**：
  - 必须将 `rs.next()` 放入 `while` 循环条件中。每次调用，游标下移一行，有数据返回 true，无数据返回 false。
  - 在循环体内，使用 `rs.getInt("数据库列名")` 或 `rs.getString("数据库列名")` 提取当前行的具体字段值。

### 六、 Druid (数据库连接池)

- **核心优势**：在系统启动时预先创建好一批连接放入“池子”里。程序需要时“借出”，用完后“归还”，彻底解决了原生 JDBC 频繁创建/销毁连接的性能瓶颈。
- **配置规范**：核心参数（url, username, password 等）需写入 `druid.properties`，且文件必须放在 Maven 项目的 `src/main/resources` 目录下。
- **加载规范**：为了防止项目打包后路径失效，**必须**使用类加载器读取：`类名.class.getClassLoader().getResourceAsStream("druid.properties")`。
- **资源释放**：使用连接池时，调用 `connection.close()` 并不是真正关闭连接，而是将其**安全归还**给连接池。

### 七、 实战：Druid + PreparedStatement 标准模板

这段代码展示了企业级开发中最标准的单表数据操作骨架（以更新数据为例）：

Java

```
import com.alibaba.druid.pool.DruidDataSourceFactory;
import javax.sql.DataSource;
import java.io.InputStream;
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.util.Properties;

public class JdbcStandardDemo {
    public static void main(String[] args) {
        Connection conn = null;
        PreparedStatement ps = null;

        try {
            // 1. 初始化 Druid 连接池 (标准类加载器读取)
            Properties prop = new Properties();
            InputStream is = JdbcStandardDemo.class.getClassLoader().getResourceAsStream("druid.properties");
            prop.load(is);
            DataSource dataSource = DruidDataSourceFactory.createDataSource(prop);

            // 2. 从连接池获取连接
            conn = dataSource.getConnection();

            // 3. 编写 SQL (使用 ? 占位符)
            String sql = "UPDATE emp SET sal = ? WHERE empno = ?";
            
            // 4. 获取预编译执行对象
            ps = conn.prepareStatement(sql);

            // 5. 安全赋值 (防 SQL 注入)
            ps.setInt(1, 10000); // 涨薪到 10000
            ps.setInt(2, 7369);  // 员工编号为 7369

            // 6. 执行 SQL
            int count = ps.executeUpdate();
            System.out.println("成功更新了 " + count + " 条数据");

        } catch (Exception e) {
            e.printStackTrace();
        } finally {
            // 7. 规范释放资源 (先开的后关，后开的先关)
            try { if (ps != null) ps.close(); } catch (Exception e) {}
            // 这里的 close 是将连接还给 Druid 连接池
            try { if (conn != null) conn.close(); } catch (Exception e) {}
        }
    }
}
```
